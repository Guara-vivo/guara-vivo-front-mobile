# Map Zone Names And Record Links Design

## Goal

Name map areas automatically by type and make new records inherit the areas that contain their coordinates.

## Decisions

- Area names are generated by type: `Alimentação A`, `Alimentação B`, `Ninho A`, `Ninho B`.
- Sequence continues after `Z` as `AA`, `AB`, `AC`.
- Deleted names can be reused by the next area of the same type.
- Users cannot rename areas.
- Areas of the same type cannot overlap.
- `feeding` can overlap `nest`.
- A record can inherit one feeding area and one nest area.
- If an area is deleted, linked records stop showing that area and fall back to `Sem área`.
- Existing areas get generated names during migration.
- Existing records do not get area links during migration.

## Backend

- Add `map_zones.name` and `map_zones.sequence_index`.
- Add `record_map_zones` join table with `record_id` and `map_zone_id` foreign keys using `ON DELETE CASCADE`.
- Generate the smallest free sequence index by type on area creation.
- Reject same-type overlap when creating an area.
- Link new records to containing areas during `POST /records/upload` and `POST /records/`.
- Return linked areas in `RecordRead`, `RecordSummaryRead`, and `RecordDetailRead`.

## Frontend

- Read `name` and `sequence_index` from map zones.
- Read `map_zones` from record responses.
- Show zone names in the selected-area card.
- Show record areas in history cards and record detail.
- Show `Sem área` when no areas are linked.

## Testing

- Backend unit tests cover sequence label generation, smallest free index selection, overlap detection, and record-area serialization.
- Frontend validation uses TypeScript and lint.

## Self-Review

No placeholders. Scope includes backend persistence and frontend display only. Deletion behavior is explicit through cascade and frontend fallback.
